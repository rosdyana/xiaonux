What people use it for

Examples from classes and security workshops. Each command runs as shown.

Classrooms

  1. Zero-install lab

    Chromebooks and locked-down PCs get a real Linux shell with no install and no account. Reset gives every student a clean machine.

    pwd && id

  2. Text-processing drills

    Count status codes in a log, pull out a field with awk, sort the unique values.

    awk '{print $9}' access.log | sort | uniq -c | sort -rn | head

  3. RISC-V assembly

    objdump and gdb read the binaries in the machine, so students see the instructions a compiler produced.

    objdump -d /bin/true | head -40

Security learners

  1. Log forensics

    Find the source addresses of failed logins in an uploaded auth.log.

    grep 'Failed password' /root/uploads/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head

  2. YARA workshop

    Write a rule for a sample and scan a folder with it.

    yara -s dropper.yar .

  3. Static deobfuscation

    Decode the hidden part of a shell dropper without running it.

    grep -o '[A-Za-z0-9+/=]\{20,\}' sample.sh | base64 -d; echo

How it works

One machine, inside one tab, on your computer.

Your browser tab

The browser's own sandbox, on your computer.

WebAssembly

The emulator, compiled to run in the page.

Emulated RISC-V CPU

Guest code never runs on your processor.

Debian 13

Your files are kept in this browser (OPFS).

  1. Starts from a snapshot

    The machine resumes from a saved state, so a warm prompt arrives in about half a second.

  2. Your changes stay

    Files you make are saved in this browser and are there next time.

  3. Reset is one button

    It deletes your changes and returns to the shipped image.

  4. Internet is your choice

    Off by default. Turn it on through the small xiaonux-net helper on your computer, or a free relay limited to pip, apt and GitHub.

Safety, plainly

What is isolated, and what isn't.

Isolated

  • Programs run on an emulated RISC-V processor inside WebAssembly, never on your computer's processor.
  • The machine can't see your files or devices. It only gets what you upload.
  • Uploads land in /root/uploads and are never marked executable.
  • Nothing you type or store is sent to a server.

Not isolated

  • With the internet on, anything you run can reach the internet from your IP address.
  • It is not a hardened malware lab. Don't analyse targeted or high-value samples here.
  • Don't put passwords or secrets in the machine.

    Internet for the machine

    The machine has no internet until you choose a way in. Everything that works offline (the shell, Python, the bundled packages and tools) needs nothing here.

    Connection

    Get xiaonux-net

    It shares your computer's internet with this tab only: web ports 80 and 443, never your local network. Run it, and it opens this page already paired.

      Start and stop

      Windows
      Start: open xiaonux-net from the Start menu. A window opens; keep it open while you use the machine.
      macOS
      Start: unzip, then double-click xiaonux-net. It runs in a Terminal window; keep it open.
      Linux
      Start: tar xzf xiaonux-net-*.tar.gz && ./xiaonux-net in a terminal, and leave it running.
      Stop
      Press Ctrl+C in its window, or close the window. It doesn't install a service and doesn't start on its own again; run it the next time you want internet here.
      The helper isn't code-signed yet

      Your system will warn the first time. Check the SHA-256 above against the file, then:

      Windows
      SmartScreen: choose More info, then Run anyway.
      macOS
      Right-click the app, choose Open, then Open again. Or run xattr -d com.apple.quarantine xiaonux-net.
      Linux
      No warning. If it won't run, make it executable: chmod +x xiaonux-net.

      What's isolated

      Programs in this machine never run on your computer's processor. They run on an emulated RISC-V processor, inside WebAssembly, inside your browser's tab sandbox. The machine can't see your files or devices; it only gets what you upload.

      What you can do with a suspicious file

      • Static analysis of any file from any system: file, strings, xxd, objdump, readelf, yara, binwalk, pefile.
      • Read and run scripts: shell, Python, Perl.
      • Run and trace RISC-V Linux programs with strace, ltrace and gdb.

      What it isn't

      • Windows, x86 and ARM programs don't run here.
      • It's not a hardened malware lab. With the internet on, anything you run can reach the internet from your IP address.
      • Don't put passwords or secrets in the machine. Follow the law and your course's rules.
